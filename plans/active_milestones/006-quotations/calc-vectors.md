# Calc Vectors (frozen oracle): 006-quotations — V1..V18

> Resolves `calc-vectors-not-inlined`. These are **hand-computed** expected values (the oracle), NOT
> generated by running the engine. `test/fixtures/quote_calc_vectors.json` must reproduce these exactly;
> `test/quote_calc.test.mjs` asserts byte-exact per vector and CI fails if < 18 present. All values are
> **integers** (paise or basis points) per `calc-spec.md §0 I0`. Primitives:
> `applyBp(base, bp) = roundHalfAwayFromZero(base*bp, 10000)`, `ceilHalf(x) = (x + (x&1))/2`,
> `roundToRupee(p)` = nearest 100 paise, 50-tie → up. Seller state `KL` (intra) unless noted.
> `itc_all` = `lines.every(itc_claimable)` (drives Finance leg: required when `!itc_all` OR grand ≥ 50000000).

Line input shorthand: `mode | pc=purchase_cost_paise, mk=markup_bp, mrp=mrp_paise, dsc=discount_bp,
fr=freight_alloc_paise, br=branding_cost_paise, pg=purchase_gst_bp, sg=sale_gst_bp, itc, qty`.
Line expected: `landed, unit, taxable, gst, cgst, sgst, igst, margin` (all paise).

**Loader invariant (every vector):** the fixtures loader asserts, per vector, `grand_total_paise ==
subtotal_paise + cgst_total + sgst_total + igst_total + round_off_paise` AND `grand_total_paise % 100 == 0`
AND every numeric field is an integer. (This check catches an inconsistent oracle entry — it is what would
have caught the original V8 `round_off` slip.)
